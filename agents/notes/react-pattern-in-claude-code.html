🔄 ReAct (Reasoning + Acting) 模式在 Claude Code 中的实现

ReAct 模式不是 React 框架，而是 LLM Agent 的核心设计范式：模型在每个周期中交替进行推理（思考当前状态）和行动（调用工具），然后观察结果并进入下一轮。这是所有 Coding Agent 的架构基石。

📋 Summary — 总体架构

Claude Code 的整个执行引擎就是 ReAct 模式的工业级实现。核心在 query.ts 的 while(true) 循环中：

每个 while(true) 迭代 = 一个 ReAct 周期

① 准备上下文           →  消息压缩/token 预算
② 模型推理 (Reason)    →  流式调用 API, 获取 thinking + tool_use
③ 解析行动 (Parse)     →  分离 thinking / text / tool_use
④ 执行行动 (Act)       →  分区并行/串行执行工具
⑤ 反馈观察 (Observe)   →  收集 tool_result, 准备下一轮

核心思想：这个循环把 LLM 的推理能力和工具执行能力连接成一个闭环。Claude Code 没有喊 "ReAct" 这个词，但每一行代码都是这个模式的产物。

🔍 Details — 各环节详解

1. 推理 (Reasoning) 的实现

Claude Code 通过 Anthropic Messages API 的 thinking 参数启用推理层：

  • adaptive thinking（Claude 4+ 模型）：自动分配推理预算，模型自行决定思考多深
  • budget thinking（旧模型）：固定 token 预算（如 16000 tokens）
  • 流式解析 thinking_delta 事件，构建独立的 contentBlock.thinking
  • 每个 thinking block 附带加密签名（signature_delta），用于完整性验证
关键文件：src/services/api/claude.ts (line ~1596-1630 配置, line ~2148-2161 流式解析)

2. 行动 (Acting) 的实现

模型输出中的 tool_use content block 触发行动执行：

// query.ts ~line 829
const msgToolUseBlocks = message.message.content.filter(
  content => content.type === 'tool_use',
)
if (msgToolUseBlocks.length > 0) {
  needsFollowUp = true  // 有工具要执行，继续循环
}

关键机制：

机制文件说明
分区执行toolOrchestration.ts并发安全工具并行，非安全工具串行
流式提前执行StreamingToolExecutor.ts边流式边执行工具，不等模型输出完
权限管道toolExecution.ts每次工具调用经过 permission → pre-hook → call → post-hook

3. 观察 (Observation) 的实现

工具执行完成后，结果以 tool_result 消息形式注入下一轮迭代：

  • StreamingToolExecutor 收集已完成工具的结果
  • 同时注入附件消息（文件变更通知、后台任务完成、memory 召回等）
  • 构建新的 state 对象：{ messages: [...旧消息, ...assistant, ...toolResults] }
  • state = next → 回到 while(true) 顶部

4. 循环决策 (Continue vs Terminate)

每次迭代结束时判断是否需要继续：

✅ 继续
  • next_turn — 常规 ReAct 继续
  • reactive_compact_retry — token 超限后压缩重试
  • max_output_tokens_recovery — 输出截断后恢复
⏹ 终止
  • completed — 正常完成
  • max_turns — 达到最大轮次
  • stop_hook_prevented — 钩子阻止
  • model_error — 模型出错

5. 上下文管理（支撑 ReAct 持续运行）

ReAct 循环能持续数十个周期，依赖精密的上下文管理机制：

机制作用
Autocompact对话太长时自动摘要旧内容，压缩到预算内
Microcompact细粒度压缩单个 tool_result，只保留关键信息
Snip大输出截断到预算以内
Token budget 跟踪每次迭代前检查剩余预算，防止超限

💡 Conclusion — 设计原则与学习建议

ReAct 模式在 Coding Agent 中的关键设计原则

  1. 循环即架构 — Agent 的本质就是一个 while(true) 循环，没有循环就没有 agent
  2. 推理与行动分离 — thinking block 代表内部推理，tool_use 代表外部行动，两者在消息数组中自然分离
  3. 观察驱动迭代 — tool_result 不是终点而是下一轮推理的输入，形成闭环
  4. 提前执行优化 — StreamingToolExecutor 在模型还在输出时就启动工具，减少 idle 时间
  5. 终止判断清晰 — 每次迭代都检查是否需要继续，避免无限循环

学习路径建议
