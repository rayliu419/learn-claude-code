Claude Code Worktree 系统设计分析

基于 git worktree 的隔离执行目录管理：Session/Agent 双路径、git/hook 双模式、安全收尾与过期清理

.claude/worktrees/{slug} worktree-{flattenedSlug} 分支 Session + Agent 双路径 git + Hook 双 VCS

一、总览

Claude Code 的 Worktree 系统是一套基于 git worktree（或 VCS hook）的隔离执行目录管理框架。它支持两种工作路径：Session Worktree（通过 EnterWorktreeTool 交互式创建使用）和 Agent Worktree（通过 createAgentWorktree() 为 AgentTool subagent 后台创建）。

核心概念对比

概念教学版 (s18)生产版 (Claude Code)

分支名wt/{name}worktree-{flattenedSlug}（/ → +）
目录约定.worktrees/{name}/.claude/worktrees/{flattenedSlug}/

创建工具worktrees.create()getOrCreateWorktree() 含快路径恢复/sparse等

二、核心数据结构

WorktreeSession { originalCwd: string // 创建 worktree 前的工作目录 worktreePath: string // worktree 目录 (.claude/worktrees/{slug}) worktreeName: string // slug 名称 worktreeBranch?: string // git 分支 (worktree-{slug}) originalBranch?: string // 创建时的当前分支 originalHeadCommit?: string // 创建时 HEAD（用于 hasWorktreeChanges 对比） sessionId: string tmuxSessionName?: string // 关联的 tmux session hookBased?: boolean // VCS hook 模式标记 creationDurationMs?: number // 创建耗时 usedSparsePaths?: boolean // 是否使用了 sparse checkout }

重要设计：WorktreeSession 只有在 Session Worktree（EnterWorktreeTool）时被设置。Agent Worktree (createAgentWorktree) 不 touch 全局 session state，每个 AgentTool 调用独立创建和删除。

三、Worktree 创建流程

createWorktreeForSession(sessionId, slug) │ ├─ validateWorktreeSlug(slug) │ └─ 长度 ≤ 64 / 无 . 和 .. / 仅 [a-zA-Z0-9._/-] │ ├─ hasWorktreeCreateHook()? │ Yes ──→ executeWorktreeCreateHook(slug) │ └─ hookBased: true │ │ No ──→ getOrCreateWorktree(gitRoot, slug) │ ├─ readWorktreeHeadSha(path) │ │ └─ 成功? → 快路径恢复（跳过 fetch/creation） │ │ │ ├─ options.prNumber? │ │ └─ git fetch origin pull/{N}/head │ │ │ ├─ resolveRef('origin/{default}') │ │ └─ 有 origin ref? → skip fetch（省 6-8s） │ │ │ ├─ git worktree add -B {branch} {path} {base} │ │ └─ -B 自动重置孤立分支 │ │ │ ├─ sparse-checkout（可选） │ │ └─ settings.worktree.sparsePaths │ │ │ └─ performPostCreationSetup() │ ├─ 复制 settings.local.json │ ├─ 配置 core.hooksPath │ ├─ 符号链接目录（node_modules 等） │ ├─ 复制 .worktreeinclude 文件 │ └─ 安装 attribution commit hook │ └─ saveCurrentProjectConfig({ activeWorktreeSession }) └─ 保存到项目配置

四、两种 Worktree 路径

Session Worktree（EnterWorktreeTool）

EnterWorktreeTool.call(input) ├─ 检查 getCurrentWorktreeSession() ← 防嵌套 ├─ process.chdir(mainRepoRoot) ← 确保从主仓库根目录创建 ├─ createWorktreeForSession(sessionId, slug) ├─ process.chdir(worktreePath) ├─ setCwd(worktreePath) ├─ setOriginalCwd() ← 更新 bootstrap state ├─ saveWorktreeState() ← session storage 持久化 └─ clearSystemPromptSections() ← 刷新环境提示词

Agent Worktree（createAgentWorktree）

// 用于 AgentTool isolation: "worktree" createAgentWorktree(slug) ├─ 不设 currentWorktreeSession ├─ 不 process.chdir ├─ 不保存 project config ├─ 复用 getOrCreateWorktree() + performPostCreationSetup() └─ 返回 { worktreePath, worktreeBranch, headCommit, gitRoot } // Subagent 运行时: AgentTool(..., isolation: "worktree") ├─ createAgentWorktree(slug) ├─ runAgent({ cwd: worktreePath }) ├─ meta.worktreePath = worktreePath ← resume 时恢复 └─ buildWorktreeNotice() → subagent prompt 注入 // 清理: removeAgentWorktree(path, branch, gitRoot) ├─ git worktree remove --force {path} ├─ git branch -D worktree-{slug} └─ git worktree prune

五、Closeout 流程

Keep（保留）

keepWorktree() ├─ process.chdir(originalCwd) ├─ currentWorktreeSession = null ├─ config.activeWorktreeSession = undefined └─ worktree 目录 + 分支完好保留 └─ 下次可通过 cd {path} 继续工作

Remove（删除 + 安全检查）

ExitWorktreeTool.call({ action: 'remove' }) │ ├─ countWorktreeChanges(worktreePath, headCommit) │ ├─ git status --porcelain → 未提交文件数 │ ├─ git rev-list HEAD --not --remotes → 未推送 commit 数 │ └─ 任何 > 0 → 必须 discard_changes: true │ ├─ cleanupWorktree() │ ├─ hook based? → executeWorktreeRemoveHook() │ ├─ git based? → git worktree remove --force {path} │ ├─ sleep(100ms) ── 等 git 释放锁 │ ├─ git branch -D worktree-{slug} │ └─ config.activeWorktreeSession = undefined │ └─ 返回变更摘要: { discardedFiles, discardedCommits }

六、Stale 过期清理

// 仅处理 ephemeral 工作树，保留用户命名的工作树 EPHEMERAL_PATTERNS = [ /^agent-a[0-9a-f]{7}$/, // AgentTool subagent /^wf_[0-9a-f]{8}-[0-9a-f]{3}-/, // WorkflowTool /^bridge-[A-Za-z0-9_]+/, // bridge session /^job-[a-zA-Z0-9._-]+-[0-9a-f]/, // template job ] cleanupStaleAgentWorktrees(cutoffDate) ├─ 扫描 .claude/worktrees/ ├─ 只处理匹配 EPHEMERAL_PATTERNS 的 slug ├─ 跳过当前 session 的 worktree ├─ 检查 mtime >= cutoffDate（默认 30 天） ├─ 安全检查: │ ├─ git status --porcelain -uno == '' │ └─ git rev-list --max-count=1 HEAD --not --remotes == ''（commits 可远程可达） ├─ removeAgentWorktree() └─ git worktree prune

九、总结

Worktree 系统设计哲学："任务系统管'做什么'，worktree 系统管'在哪做且互不干扰'。"

生产版从教学版 s18 的"task → worktree 绑定 + closeout 动作"模型演化为双路径（Session + Agent）+ 双模式（git + hook）+ 安全收尾 + 过期清理的完整框架。核心设计差异源于生产需求：worktree 需要同时支持交互式 Session（Enter/Exit）和后台 Agent（创建/删除）两种独立使用方式，需要 fast-resume 优化重复进入的延迟，需要通过 stale cleanup 处理进程崩溃残留。

关键设计权衡

隔离性✅ git worktree 提供完整目录隔离，互不干扰
安全性✅ slug 防穿越 + stale 模式防误删 + countWorktreeChanges 防数据丢失
灵活性✅ git + hook 双 VCS + sparse checkout + 目录符号链接
性能✅ 快速恢复路径（无子进程）+ -B 免强删 + fetch 跳过
资源占用⚠️ 每个 worktree 独立 .git 目录占用磁盘
复杂度⚠️ hook + git + tmux + symlinks 多模式组合
