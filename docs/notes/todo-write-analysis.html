TodoWrite 实现分析

Claude Code 中"Todo"功能的完整实现链路。核心结论：TodoWrite 是一个有状态工具 + 附带的提醒注入机制，提示词只是教模型"怎么用这个工具"。

Summary

Todo 不是 system prompt 里的一段话，而是一个完整的 Tool 实现：它有自己的 Zod schema、AppState 存储、自动提醒注入、断点恢复、UI 渲染和子 agent 生命周期管理。System prompt 里出现在工具定义中的是它的"使用说明书"（prompt.ts），但真正的状态管理在工具之外。

3. 调用链

3.1 TodoWriteTool.call()

async call({ todos }, context) {
  const todoKey = context.agentId ?? getSessionId()
  const oldTodos = appState.todos[todoKey] ?? []
  const allDone = todos.every(_ => _.status === 'completed')
  const newTodos = allDone ? [] : todos  // 全部完成→清空

  // 验证 nudge: 3+ 项任务完成但没有 verification 步骤
  if (allDone && todos.length >= 3 &&
      !todos.some(t => /verif/i.test(t.content))) {
    verificationNudgeNeeded = true
  }

  context.setAppState(prev => ({
    ...prev, todos: { ...prev.todos, [todoKey]: newTodos }
  }))
}

3.2 mapToolResultToToolResultBlockParam()

mapToolResultToToolResultBlockParam({ verificationNudgeNeeded }, toolUseID) {
  const base = "Todos have been modified successfully. ..."
  const nudge = verificationNudgeNeeded
    ? "\n\nNOTE: You just closed out 3+ tasks and none was a verification step. "
      "Spawn the verification agent before writing your final summary."
    : ''
  return { tool_use_id: toolUseID, type: 'tool_result', content: base + nudge }
}

3.3 自动提醒注入（attachments.ts）

turnsSinceLastTodoWrite >= TODO_REMINDER_CONFIG.TURNS_SINCE_WRITE (6)
&& turnsSinceLastReminder >= TODO_REMINDER_CONFIG.TURNS_BETWEEN_REMINDERS (3)
  → 创建 todo_reminder attachment，内容为当前 todos 快照
  → 注入到消息历史

4. 关键设计点

设计说明
shouldDefer: true工具调用延迟执行，不阻塞主流程
renderToolUseMessage() → null不在 UI 中渲染多余文本
全部完成→清空列表allDone ? [] : todos—完成即清理，避免 stale 数据
agentId 隔离每个 agent（父/子）有独立的 todo key，不会互相干扰
最多 12 项教学版直接限制；生产版在 prompt 中指导模型不要超过合理数量
verification nudge3+ 任务完成但没有验证步骤时自动提示，防止跳过检查

6. 结论

TodoWrite 不是"一段提示词"，而是一个完整的控制面工具。

  • 它的"工具定义"（name, schema, description）是提示词的一部分
  • 它的"使用说明"（prompt.ts）也是提示词的一部分（教模型怎么用）
  • 但它的状态存储、自动提醒、断点恢复、UI 渲染、子 agent 生命周期绑定，全都在提示词之外

所以如果你把 TodoWrite 理解为"系统提示词里的一段话"，只看到了它作为工具暴露给模型的那一面。它真正的复杂度在于工具之外的状态管理和副作用机制。
