Claude Code 工具系统

Claude Code 采用高度工程化的工具架构，包含约 50+ 内置工具，覆盖文件操作、代码搜索、子代理调度、权限控制、工作流编排等能力。系统基于统一类型接口，通过中央注册表管理所有工具。

一、工具定义与注册

1.1 核心接口

文件: src/Tool.ts (第 362-695 行)

所有工具必须满足 Tool<Input, Output> 类型契约，核心字段包括：

  • name — 唯一标识工具名
  • aliases — 兼容旧版对话的别名
  • call() — 实际执行函数
  • inputSchema — Zod 参数校验模式
  • description() / prompt() — 模型阅读的描述
  • isEnabled / isConcurrencySafe / isReadOnly / isDestructive — 安全/并发属性
  • shouldDefer — 是否延迟加载（推迟到模型通过 ToolSearch 查询时才发送）
  • checkPermissions() — 权限检查逻辑
  • maxResultSizeChars — 大结果持久化阈值

工具构建函数: buildTool() (第 783-792 行) 从部分定义补全默认值，减少各工具的样板代码。默认值定义在 TOOL_DEFAULTS (第 757-769 行)。

1.2 中央注册表

文件: src/tools.ts

getAllBaseTools() (第 193-251 行) 是所有内置工具的单一收集点。工具可基于以下条件有条件地包含：

  • 环境变量
  • 编译期特性开关 feature()
  • 用户类型 USER_TYPE（普通用户 vs Ant 员工）
  • 运行时的 MCP 服务可用性
注册后处理流程:
getAllBaseTools() → getTools(permissionContext)（按模式过滤）→ filterToolsByDenyRules()（移除拒绝的工具）→ assembleToolPool(mcpTools)（合并 MCP 工具、去重、排序）

1.3 注册机制特点

  • 非 class 继承：对象字面量 + buildTool() 工厂模式
  • 静态注册：启动时注册完毕，无运行时动态注册（MCP 工具除外）
  • 条件编译：feature() 控制实验性工具的包含
  • 延迟加载：shouldDefer 推迟重型工具的定义传输

三、工具执行流水线

3.1 总体架构（5 层）

Layer 1: 工具注册 (tools.ts)
  getAllBaseTools() → getTools() → assembleToolPool()

Layer 2: API 序列化 (utils/api.ts)
  toolToAPISchema() → BetaToolUnion → API tools[] 参数

Layer 3: 流式执行 (StreamingToolExecutor.ts)
  并行调度 → 结果缓冲 → 按序发射

Layer 4: 编排 (toolOrchestration.ts)
  runTools() → partitionToolCalls() → concurrent/serial 批处理

Layer 5: 单工具执行 (toolExecution.ts)
  校验 → Hook → 权限 → 执行 → 后处理

3.2 单工具执行流程

核心函数: checkPermissionsAndCallTool() — src/services/tools/toolExecution.ts (第 599 行)

  1. Zod Schema 校验 — 参数格式验证，失败返回 InputValidationError
  2. 自定义校验 — validateInput() 处理超出 Schema 的逻辑（如文件存在性）
  3. 输入回填 — backfillObservableInput() 为 Hook/权限添加遗留字段
  4. PreToolUse Hooks — 可做权限决策、修改输入、阻止执行
  5. 权限检查 — 集成 Hook 决策 + 规则权限 + 用户弹窗 + 自动分类器
  6. 工具执行 — tool.call() 运行实际逻辑
  7. PostToolUse Hooks — 后置处理
  8. 结果处理 — 映射 API 响应、大结果持久化、UI 渲染
并发模型: 并发安全工具（如 Sleep、不同文件的 Read）并行执行；非安全工具串行执行。结果按模型返回顺序缓冲发射，保持因果序。

3.3 权限安全体系

  • 规则权限 — always-allow / always-deny / always-ask 三种策略
  • Hook 决策 — 通过 PreToolUse Hook 自定义权限逻辑
  • 用户弹窗 — 直接向用户请求授权
  • 自动分类器 — Auto Mode 下自动判断
  • 拒绝追踪 — 连续拒绝后临时自动拒绝

结论

  • 统一契约：所有工具遵循同一类型接口，结构一致可预测
  • 集中注册：单一注册点保证完整性，避免分散注册的遗漏
  • 分层权限：Hook → 规则 → 用户交互，5 层安全防护
  • 灵活并发：并发安全声明 + 流式执行器实现高效并行调度
  • 条件可用性：特性开关、环境变量、用户类型多维度控制工具可见性
  • MCP 扩展：MCP 工具作为一等公民与内置工具统一处理
